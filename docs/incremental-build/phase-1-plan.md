# Phase 1: Minimal Viable Incremental Build

**Status**: Planning
**Prerequisite**: [design.md](./design.md) — the full architecture document

---

## Goal

Get an end-to-end incremental build working with conservative dirty detection:

- Content digest diffing for MDX/MD pages (the common case)
- Full rebuild fallback for any non-content source file change
- Full rebuild fallback for partial/data collection changes

This captures the primary use case for cloudflare-docs: PRs that only edit MDX content pages, which represent the vast majority of changes.

The data store uses devalue serialization. Each `DataEntry` has a `digest` field (xxhash64 of raw file contents) computed by the glob loader. The build output uses `build.format: "directory"`, so `dist/workers/get-started/guide/index.html` is the output for entry ID `workers/get-started/guide`.

## Dirty Detection Algorithm (Phase 1)

```
1. LOAD PREVIOUS STATE
   - Read dist-meta/data-store.json (devalue-serialized Map<collection, Map<id, DataEntry>>)
   - Read dist-meta/component-manifest.json ({ [relativePath]: hash })

2. GLOBAL FILE CHECK
   - Hash files matching incrementalBuild.globalFiles patterns
     (defaults: ['astro.config.*', 'package.json'])
   - Compare against component-manifest.json
   - If ANY changed → return null (full rebuild)

3. NON-CONTENT SOURCE FILE CHECK (Phase 1 conservative)
   - Hash ALL files in src/ that are NOT under content collection directories
     (i.e., src/components/, src/layouts/, src/styles/, src/plugins/,
      src/pages/, src/middleware/, src/schemas/, src/scripts/, src/util/, etc.)
   - Compare against component-manifest.json
   - If ANY changed → return null (full rebuild)
   - Phase 2 will narrow this to per-component import tracking

4. CONTENT ENTRY DIFF
   For each collection in the current data store:

   a) "docs" collection (and "changelog", "compatibility-flags"):
      - Compare digests per entry (current vs previous)
      - New entry (exists in current, not previous) → dirty
      - Changed entry (digest differs) → dirty
      - Deleted entry (exists in previous, not current) → add to cleanup set
      - Map dirty entry IDs to pathnames

   b) "partials" collection:
      - If ANY partial entry changed → return null (full rebuild)
      - Phase 2 will use partialResolver to narrow this

   c) Data collections (glossary, plans, directory, workers-ai-models, etc.):
      - If ANY data entry changed → return null (full rebuild)
      - These feed into pages unpredictably

   d) Meta collections (meta::meta, meta:*):
      - Skip (internal state, not content)

5. MAP ENTRY IDs TO PATHNAMES
   For docs collection entries:
     entryId → pathname: entryId === '' ? '/' : '/' + entryId

   For changelog entries:
     Changelog pages are at /changelog/<slug> (from [...changelog].xml.ts and
     changelog/ routes in src/pages/). However, these are src/pages/ routes,
     not content collection routes. For Phase 1, any changelog change triggers
     full rebuild (handled by step 4b since changelog changes affect src/pages/
     routes that iterate the collection).

   Simplification for Phase 1: Only diff the "docs" collection entries.
   All other collection changes → full rebuild.

6. RETURN
   - Set<string> of dirty pathnames, or null for full rebuild
   - Cleanup set (deleted entry pathnames) attached for copyCleanPages
```

## Entry ID to Pathname Mapping

The `[...slug]` route (injected by Starlight) calls `getStaticPaths()` which returns `PathWithRoute[]`. The `pathname` field is generated by `getRouteGenerator()` from `stringifyParams()`.

For cloudflare-docs (no i18n, trailingSlash: "ignore"):

| Entry ID                    | `slugToParam()`               | Pathname from `getStaticPaths()` |
| --------------------------- | ----------------------------- | -------------------------------- |
| `""` (root, from index.md)  | `undefined` → spread `""`     | `/`                              |
| `workers`                   | `"workers"`                   | `/workers`                       |
| `workers/get-started/guide` | `"workers/get-started/guide"` | `/workers/get-started/guide`     |

The `generate.ts` filter normalizes with `removeTrailingForwardSlash()`, so the dirty set should contain values like `/workers/get-started/guide` (no trailing slash, leading slash).

**Mapping function:**

```ts
function entryIdToPathname(entryId: string): string {
  return entryId === '' ? '/' : '/' + entryId;
}
```

**Reverse mapping (pathname to output file):**

```ts
function pathnameToOutputFile(pathname: string, buildFormat: string): string {
  if (pathname === '/') return 'index.html';
  // build.format: "directory" (default)
  return pathname.slice(1) + '/index.html';
}
```

### 4. `packages/astro/src/core/build/incremental.ts` — **New file**

Three exported functions plus types:

```ts
export interface IncrementalBuildOptions {
  settings: AstroSettings;
  routesList: RoutesList;
  logger: Logger;
}

export interface IncrementalBuildResult {
  dirtyPathnames: Set<string>;
  cleanupPathnames: Set<string>; // deleted pages to NOT copy from previous
}

/**
 * Compute which pathnames need rebuilding. Returns null if full rebuild required.
 */
export async function computeDirtyPathnames(
  opts: IncrementalBuildOptions,
): Promise<IncrementalBuildResult | null>;

/**
 * Copy unchanged HTML pages from previousDist into the current outDir.
 */
export async function copyCleanPages(opts: {
  previousDist: URL;
  outDir: URL;
  result: IncrementalBuildResult;
  logger: Logger;
}): Promise<void>;

/**
 * Persist metadata artifacts for the next incremental build.
 */
export async function persistBuildMetadata(opts: { settings: AstroSettings }): Promise<void>;
```

#### `computeDirtyPathnames` implementation outline:

1. Resolve `dist-meta/` path from `previousDist` (sibling directory)
2. Read `dist-meta/data-store.json` — parse with devalue
3. Read `dist-meta/component-manifest.json` — parse as JSON
4. Read current data store from `settings.config.cacheDir` + `data-store.json`
5. **Global files check**: Use `tinyglobby` to expand `globalFiles` patterns, hash each with xxhash, compare against manifest
6. **Non-content files check**: Walk `src/` excluding content collection directories, hash all files, compare against manifest
7. **Content diff**: Compare `docs` collection entries by digest
8. **Other collections**: If any non-docs collection has changes → return null
9. Build dirty pathname set and cleanup set

#### `copyCleanPages` implementation outline:

1. Walk `previousDist/` recursively for `.html` files
2. Skip `_astro/`, `_headers`, `__redirects`, `sitemap-*.xml`, `robots.txt` (regenerated)
3. For each HTML file, derive pathname from relative path
4. If NOT in `dirtyPathnames` and NOT in `cleanupPathnames` → copy to outDir
5. Log count of copied pages

#### `persistBuildMetadata` implementation outline:

1. Create `dist-meta/` directory (sibling of outDir)
2. Copy current data-store.json from cacheDir
3. Compute component manifest: hash all files in src/ + globalFiles patterns
4. Write component-manifest.json

### 5. `packages/astro/src/core/build/index.ts`

In the `build()` method:

**After `runHookBuildStart()` (line 190), before `viteBuild()` (line 239):**

```ts
let incrementalResult: IncrementalBuildResult | null = null;

if (this.settings.config.previousDist) {
  const { computeDirtyPathnames } = await import('./incremental.js');
  incrementalResult = await computeDirtyPathnames({
    settings: this.settings,
    routesList: this.routesList,
    logger: this.logger,
  });

  if (incrementalResult !== null) {
    this.logger.info(
      'build',
      `Incremental: ${incrementalResult.dirtyPathnames.size} pages to rebuild`,
    );

    // Wrap prerenderer to filter getStaticPaths() to dirty pages only
    const existingPrerenderer = this.settings.prerenderer;
    this.settings.prerenderer = (defaultPrerenderer) => {
      const base =
        typeof existingPrerenderer === 'function'
          ? existingPrerenderer(defaultPrerenderer)
          : (existingPrerenderer ?? defaultPrerenderer);
      return {
        ...base,
        async getStaticPaths() {
          const all = await base.getStaticPaths();
          return all.filter(({ pathname }) => incrementalResult!.dirtyPathnames.has(pathname));
        },
      };
    };
  } else {
    this.logger.info('build', 'Incremental: full rebuild required.');
  }
}
```

## Known Limitations (Phase 1)

| Limitation                                                  | Impact                                                                    | Phase 2 fix                                                       |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Any non-content src/ change triggers full rebuild           | Component-only changes still get full builds                              | Component import scanning + reverse dependency map                |
| Any partial change triggers full rebuild                    | Editing a partial used by 1 page rebuilds everything                      | `partialResolver` + partial→page reverse map                      |
| Any data collection change triggers full rebuild            | Editing glossary/plans/directory data rebuilds everything                 | Collection→route dependency tracking                              |
| Non-content-collection routes (src/pages/) always rebuilt   | RSS, LLM txt, search, etc. are always regenerated                         | Route-level dependency tracking                                   |
| Shared CSS/JS chunks may differ between partial/full builds | \_astro/ contents from partial build may include only dirty pages' chunks | Chunk content-hashing means this works (same content = same hash) |

## Open Questions

1. **Vite chunk consistency**: When only a subset of pages are rendered, does Vite still produce the same CSS/JS chunk hashes? The prerender environment build still bundles ALL routes (the data store virtual module includes everything), so Rollup should produce identical chunks. The filtering only affects which pages get rendered to HTML. This should be fine but needs verification.

2. **Image optimization**: The image optimization step in `generate.ts` runs after page generation. For an incremental build, we only optimize images referenced by dirty pages. Clean pages' images should already be in the previous build's output. We may need to copy optimized images from `previousDist/_astro/` as well.

3. **Sitemap**: The sitemap plugin scans `dist/` for HTML files after `copyCleanPages` runs (since it fires in `astro:build:done`). This should produce a correct complete sitemap. Verify.
